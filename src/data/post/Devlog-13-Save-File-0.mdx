### **What Is Save File 0?**

You're covering the night QA shift at **Oriole Software**. Their new build has a save bug that nobody can reproduce. Mara was looking into it, but she isn't answering her phone. Her handover note is simple: make a save, load it back, write down anything odd.

So you make a save. Then you open the save index, and there's a second file under yours.

**00 FILE 0.** No time. No owner.

Load it and you're back in the same office. Same desk, same copier, same corridors. Except Mara's revolver is lying on the reception counter, with a note under it: *Don't touch slot 0. If you loaded it, take this. It only buys a few seconds.* And you're not alone in the building any more.

### **Why a QA Tester?**

I've spent over nine years in games QA, and anyone who's done the job knows this feeling. You're in late, the office is empty, and there's a save bug that only happens when nobody's watching. The build is doing something it shouldn't, and you can't prove it.

That's where Save File 0 starts. I wanted the scary part to come from the **save system itself**, and it turns out a Game Boy cartridge is surprisingly good at that. More on that in a bit.

### **Two Saves, One Office**

The whole game is built around one idea: **each save file is its own copy of the building**, and when you load a save, you load in exactly where you're standing.

Your own save is the ordinary office. It's quiet, and it's where you patch yourself up. FILE 0 is the same office, but wrong, and it's where things hunt you.

Most of the puzzles come from switching between the two:

- **A door you open in your save stays open in FILE 0.**
- **Server racks block a room in FILE 0**, but they aren't there in your save. So you walk round them in your save, then load FILE 0 on the other side.
- So a lot of the game is about choosing **where to stand** before you load.

And sometimes FILE 0 leaks back the other way. Visit it, load your own save again, and things aren't quite how you left them.

### **The Occupant**

The thing in FILE 0 can't be killed. A shot staggers it for a few seconds, and that's all you get.

You'll usually hear it before you see it. Its footsteps come from the side it's on and get louder as it gets closer, and if the hum in the building suddenly cuts out, it's about to come through a door. Your options are the old ones: break its line of sight, or find a locker and keep very still. Just don't let it see you climb in.

And because everyone asks how you run away from something on a D-pad: **B + Down** spins you round 180° on the spot, and holding **B** turns Left and Right into a sidestep.

### **Getting a Game Boy Color to Do This**

The Game Boy Color was never meant to run a first-person game. Save File 0 uses a **raycaster**: 40 rays across the screen, drawn as four-pixel wall columns, aiming for a steady **30 frames per second** using the GBC's double-speed mode.

Drawing the picture is the easy bit. The hard part is getting it onto the screen. The Game Boy only lets you touch video memory during a tiny gap between frames, about **ten scanlines** long. The finished frame, the HUD, the minimap and the colour palettes all have to share that gap. A lot of the work so far has been fitting everything in, and catching the cases where something quietly misses its slot. The minimap, for example, used to freeze whenever you moved, because it kept missing the gap.

Sound uses all four of the Game Boy's channels: the building's hum, your heartbeat, footsteps, doors and the odd creak you'd rather not think about.

So far I've been testing in emulators, including one set up to copy the real hardware's timing. In that one, build 18 holds 30 frames per second in every room, even with the Occupant and three crawlers in the corridor at once. The real proof is the cartridge, though. Next up is playing it on my own Game Boy Color from a real cartridge, and I'll film that for the next devlog.

It's written in C and assembly with **GBDK**, and I use AI tools to help with the programming side.

### **Built Like a QA Tester**

Most of the changes come from playing it and writing notes like I would for any bug report. A few favourites:

- **The game used to explain its own rules on screen.** It doesn't any more. You find out what FILE 0 does by loading it.
- **There were six first aid kits in the game, all hidden in shelves**, and nobody found any of them. Now there are cases you can actually see.
- **In one build you could get yourself stuck** somewhere your save wouldn't load. I fixed it and added a test so it can't come back. That one's the QA brain again.
